## Commands

```bash
pnpm --filter storyproof build       # tsdown (ESM + declarations; publint + attw gates)
pnpm --filter storyproof test        # vitest (node unit tests, incl. the pack-inventory snapshot)
pnpm --filter storyproof test:visual # playwright acceptance suite
pnpm --filter storyproof typecheck   # tsc --noEmit
pnpm --filter storyproof lint        # oxlint --deny-warnings
```

Normal visual runs start from the Storybook **Visual tests** panel or widget,
not a CLI.

## Structure

Split by execution environment — the boundary is load-bearing.

| Path           | Runs in                 | Contents                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/node/`    | Storybook server (Node) | `runner.ts` (`VisualTestRunner`: run/cancel/approve state machine), `capture.ts` (Chromium session, content clip, render-fingerprint probe), `environment.ts`, `container.ts` (containerized capture; measured rationale in its comments), `compare.ts` (pixelmatch policy, baseline metadata schema 2), `paths.ts`, `approval.ts`, `story-index.ts`, `server.ts` (artifact route + command endpoint) |
| `src/manager/` | Browser (manager UI)    | `PanelView.tsx` (pure view), `Panel.tsx` / `TestProviderRow.tsx` (wiring), `state.ts`                                                                                                                                                                                                                                                                                                                 |
| `src/shared/`  | Both                    | `protocol.ts` (commands), `results.ts` (`VisualResult` / `VisualRunState` / `VisualCaptureMode`)                                                                                                                                                                                                                                                                                                      |
| `test/`        | —                       | vitest unit tests; `acceptance/addon-suite.ts` the reusable spec; `smoke/` playwright; `fixtures/project` the fixture Storybook                                                                                                                                                                                                                                                                       |

Entry points are `index.ts`, `manager.tsx`, `preset.ts`, `preview.ts` — see the
`exports` map in `package.json`.

## Gotchas

- **`node/` never imports `manager/`, and vice versa** — they run in different
  processes. Shared shapes go through `src/shared/`.
- **Artifact paths are a security surface.** `paths.ts` (`assertPathSegment`,
  `isWithin`, `normalizeImportPath`) keeps every read and write inside the
  source-adjacent `__screenshots__/…` tree; a story id or import path is
  attacker-adjacent input. Never build an artifact path that bypasses these
  guards.
- **`VisualTestRunner` holds two coupled stores** — public `state.results` (what
  the UI renders) and private `completed` (approval candidates, keyed
  `runId\0storyId\0environmentKey`). `approve()` requires a matching `completed`
  entry and a candidate-hash match or it throws stale-approval; keep the two in
  sync.
- **Dev-only by construction.** Approval writes files, so the panel reports
  unavailable in static builds. Never add a code path that writes from a non-dev
  context.
- **Don't rename the `.visual` suffix** on artifact directories — it keeps
  Storybook's story glob from mistaking an artifact dir for a story file.
- **`pnpm pack` always rebuilds** via `prepack`, so a stale `dist` can never be
  packed. `test/pack-inventory.test.ts` packs the package and asserts the
  tarball ships only `dist/**`, `LICENSE`, `README.md`, and `package.json`
  within a 150 KiB budget — there is no separate inventory script.

## Acceptance suite

`test:visual` runs `test/acceptance/addon-suite.ts` against
`test/fixtures/project`, copied to `test/.tmp/project` by
`test/fixture-server.ts`.

- `VISUAL_TEST_PROJECT_DIR=<path>` points the same suite at a real installed
  project instead — no copy, and the child Storybook's `cwd` becomes that
  directory so `storyproof/preset` resolves from its real `node_modules` rather
  than workspace source. CI's `consumer` job sets it to a packed-tarball install
  of an example ([examples/AGENTS.md](../../examples/AGENTS.md)).
- The two fault-injection scenarios (simulated hang, forced connection failure)
  skip automatically when the target has no `control/state.json` — only
  `test/fixtures/project` carries that fixture.
